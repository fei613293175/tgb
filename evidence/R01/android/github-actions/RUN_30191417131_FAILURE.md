## 原因

工作流假设 `sdkmanager` 已直接进入 GitHub runner 的 `PATH`。实际 runner 具备 Android SDK，但该命令没有裸命令入口，因此在安装锁定的 Android 37 platform/build-tools 前停止。后续 Gradle、模拟器和截图步骤均被正确跳过。

Artifact 步骤因前序未产生任何文件又报告一次失败，遮蔽了主因；旧 `upload-artifact@v4` 还产生 Node.js 20 弃用警告。

## 修复

- 从 `$ANDROID_HOME/cmdline-tools/**/bin/sdkmanager` 定位真实可执行文件并断言存在；
- 单独检查 `sdkmanager --licenses` 的退出码，不让 `yes` 的 SIGPIPE 干扰 `pipefail`；
- `upload-artifact` 固定升级到 v6 的完整 commit SHA；
- 前序构建没有任何产物时 Artifact 改为 warning，保留真正失败步骤为唯一主因。
